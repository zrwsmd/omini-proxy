# 分组管理功能修复说明

## 修复的问题

### 1. ✅ 新建分组后不显示
**问题描述：** 新建分组后，分组标签不会立即显示，需要重启软件才能看到。

**原因分析：** `CreateNewGroup` 方法只调用了 `RebuildNodeGroups()`，但该方法只从现有节点中提取分组名称，新建的空分组不会被包含。

**修复方案：**
- 新建分组后立即添加到 `_nodeGroups` 集合
- 添加重复检查，防止创建同名分组
- 添加"全部"名称检查，防止使用保留名称
- 提供用户反馈信息

**修复代码：**
```csharp
// 立即添加到 NodeGroups 显示
if (!_nodeGroups.Contains(newGroup, StringComparer.OrdinalIgnoreCase))
{
    _nodeGroups.Add(newGroup);
}
```

---

### 2. ✅ 删除分组会删除多个分组
**问题描述：** 删除一个分组时，可能会误删除其他分组。

**原因分析：** `RebuildNodeGroups()` 方法只从节点中提取分组，删除节点后，其他空分组也会被移除。

**修复方案：**
- 修改 `RebuildNodeGroups()` 方法，同时从节点和 `_subscriptionGroups` 中收集分组
- 这样即使分组下没有节点，空分组也能保留

**修复代码：**
```csharp
// 同时从节点和订阅分组中收集
var nodeGroups = _nodes.Select(n => n.Node.SubscriptionGroup)...;
var subscriptionGroupNames = _subscriptionGroups.Select(s => s.GroupName)...;
var allGroups = nodeGroups.Union(subscriptionGroupNames, ...)...;
```

---

### 3. ✅ 删除所有节点时分组也被删除
**问题描述：** 移除一个分组下的所有节点后，该分组标签也消失了。

**原因分析：** 同问题 2，`RebuildNodeGroups()` 只从节点中提取分组。

**修复方案：** 同问题 2 的修复方案，保留 `_subscriptionGroups` 中的空分组。

---

### 4. ✅ 删除分组弹框不够现代化
**问题描述：** 使用的是系统默认的 `MessageBox`，样式老旧，不符合现代 UI 设计。

**修复方案：**
- 创建现代化的 `ConfirmWindow` 对话框
- 使用圆角、阴影、现代配色
- 显示节点数量，提供更详细的信息
- 区分危险操作（红色按钮）和普通操作（蓝色按钮）

**新增文件：**
- `Views/ConfirmWindow.xaml` - 现代化确认对话框 UI
- `Views/ConfirmWindow.xaml.cs` - 对话框逻辑

**效果对比：**

**修复前：**
```

确定要删除分组"测试"及其包含的所有节点吗？
(注意: 节点及关联信息将被彻底移除)

```

**修复后：**

## 技术细节

### 分组数据源
分组标签 (`_nodeGroups`) 现在从两个来源收集：
1. **节点分组** - 从 `_nodes` 中提取 `SubscriptionGroup`
2. **订阅分组** - 从 `_subscriptionGroups` 中提取 `GroupName`

### 数据持久化
- 分组信息保存在 `_subscriptionGroups` 集合中
- 通过 `PersistSelectionAsync()` 保存到配置文件
- 重启软件后自动恢复分组

### UI 更新机制
- 使用 `ObservableCollection<string>` 实现自动 UI 更新
- 新建分组后直接添加到集合，无需重建
- 删除分组后通过 `RebuildNodeGroups()` 清理

---

## 注意事项

1. **"全部" 是保留分组名称**，不能创建或重命名为该名称
2. **删除分组会同时删除其下所有节点**，操作不可撤销
3. **空分组会被保留**，直到手动删除
4. **分组名称不区分大小写**，"Test" 和 "test" 视为同一分组
